# Архитектура сервиса pg-compare (CLI, Java 25 + Spring Boot 4 + Lombok)

## Общий вид
CLI-приложение на picocli (официально рекомендованный путь для Spring Boot CLI): `SpringApplication` поднимает контекст, а `CommandLine Runner` запускает команду сравнения. Выход: JSON-отчёт + .sql файл с DDL.

```
java -jar pg-compare.jar \
  --source-url=jdbc:postgresql://host1/db1 --source-user=... [--source-password=...] \
  --target-url=jdbc:postgresql://host2/db2 --target-user=... [--target-password=...] \
  --schema=public \
  --out=report.json --ddl=migration.sql
```

Пароль через опцию, переменную окружения (`PGCOMPARE_PASSWORD_SOURCE/TARGET`) или интерактивный prompt (picocli `interactive = true`).

## Структура модулей (single module, package-by-feature)

```
com.anri.pgcompare
├── PgCompareApplication          — Spring Boot entry point
├── cli/
│   └── CompareCommand            — @Command(picocli), options, валидация, оркестрация
├── config/
│   └── AppConfig                 — бины DataSourceFactory, ObjectMapper
├── connection/
│   └── ConnectionProvider        — создаёт JDBC-подключение по URL/credentials (не пул — одноразовое)
├── extractor/                    — чтение метаданных через JDBC DatabaseMetaData + информационные схемы
│   ├── SchemaExtractor           — фасад: собирает SchemaSnapshot
│   ├── TableExtractor            — таблицы, колонки (тип, nullable, default)
│   ├── ConstraintExtractor       — PK, FK, UNIQUE, CHECK
│   ├── IndexExtractor            — индексы, sequences
│   └── SequenceExtractor
├── model/
│   ├── SchemaSnapshot            — иммутабельное представление схемы БД (records + Lombok)
│   ├── TableDef, ColumnDef, ConstraintDef, IndexDef, SequenceDef
│   └── типы-перечисления (ConstraintType и т.п.)
├── diff/                         — ядро сравнения (чистая логика, без I/O — легко тестируется)
│   ├── SchemaDiffer              — сравнивает два SchemaSnapshot → SchemaDiff
│   ├── DiffEntry                — object type, object name, change type (ADDED/REMOVED/MODIFIED), before/after, severity (BREAKING/NON_BREAKING/INFO)
│   └── SeverityClassifier       — DROP TABLE / DROP COLUMN = BREAKING, ADD INDEX = NON_BREAKING и т.д.
├── ddl/
│   └── DdlGenerator              — SchemaDiff → миграционный SQL (CREATE/ALTER/DROP, корректный порядок: сначала таблицы, потом FK)
├── report/
│   ├── JsonReportWriter          — дифф → report.json (Jackson)
│   └── ConsoleSummaryPrinter     — краткая сводка в консоль + exit code (0 = схемы идентичны, 1 = есть отличия, 2 = ошибка)
└── exception/
    └── CompareException          — единая обёртка ошибок
```

## Ключевые решения

1. **Извлечение метаданных.** Основной источник — PostgreSQL `pg_catalog` / `information_schema` запросами через JdbcTemplate (даёт полную картину: default-значения, выражения индексов, deferrable FK), `DatabaseMetaData` — только как дополнение. Подключение — обычный `DriverManager`, без HikariCP (CLI живёт секунды). Catalog `pg_catalog` фиксирован по версиям 13–17, в коде это изолировано в extractor-слое.

2. **Snapshot-модель.** Сначала обе схемы полностью вычитываются в иммутабельные `SchemaSnapshot` (Java 25 records, sealed-иерархии где уместно, Lombok @Value для билдеров), затем сравнение идёт в памяти. Это разделяет I/O и логику, делает differ unit-тестируемым без БД.

3. **Сравнение.** `SchemaDiffer` идёт по категориям (таблицы → колонки → констрейнты → индексы → sequences), для каждого объекта вычисляет ADDED/REMOVED/MODIFIED. Ключи — нормализованные имена (lowercase, если БД не хранит их в кавычках). Типы колонок сравниваются нормализованно (`varchar` == `character varying`, с учётом длины/precision).

4. **DDL-генерация.** `DdlGenerator` выдаёт SQL с корректным порядком зависимостей: CREATE TABLE → PK/UNIQUE → индексы → FK в конце (или `--disable-triggers`-стиль). Только MODIFY через `ALTER`; для переименований не угадываем — генерируем DROP+ADD с комментарием. DDL идемпотентен по желанию (`IF NOT EXISTS` / `IF EXISTS`).

5. **Тесты.** JUnit 5 + Testcontainers (PostgreSQL): integration-тесты создают две схемы, применяют DDL, проверяют дифф. Unit-тесты differ/ddl на захардкоженных snapshot'ах.

## План реализации (порядок работ)
1. Скелет проекта: pom.xml (Java 25, Spring Boot 4.0.x), Application, picocli-команда с опциями и help
2. model/ — records для snapshot и diff
3. extractor/ — запросы к pg_catalog, сборка SchemaSnapshot
4. diff/ — SchemaDiffer + SeverityClassifier
5. ddl/ — DdlGenerator
6. report/ — JSON writer, консольная сводка, exit codes
7. Тесты: unit на differ/ddl, Testcontainers integration
8. README с примерами запуска
