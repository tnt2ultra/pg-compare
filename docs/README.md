# Документация pg-compare

Комплект документации, составленный **постфактум**: поведение описано так, как оно реализовано в
коде и зафиксировано тестах. Если документ и код расходятся, источник истины — код и тесты.

Версия продукта: `0.1.0-SNAPSHOT`. Дата актуализации: 30.08.2026.

## Соглашения по терминам

Дальше по всем документам используются одни и те же обозначения.

| Термин | Значение |
|---|---|
| **источник** (`source`) | база/схема, которая **мигрируется**; её состояние — «как есть». К ней применяется сгенерированный скрипт |
| **цель** (`target`) | база/схема с **желаемым** состоянием; она не изменяется |
| **снимок схемы** (`SchemaSnapshot`) | неизменяемая модель одной схемы в памяти: таблицы с колонками, констрейнты, индексы, sequence |
| **запись диффа** (`DiffEntry`) | один элемент отчёта: тип объекта, имя, тип изменения, severity, текстовое описание, определения до/после |
| **`ADDED` / `REMOVED`** | направление фиксировано: `ADDED` — объект есть только в цели (его надо создать), `REMOVED` — только в источнике (его надо удалить) |
| **severity** | `BREAKING` / `NON_BREAKING` / `INFO` — оценка опасности изменения для работающих приложений |
| **артефакты** | файлы, которые утилита пишет на диск: JSON-отчёт и миграционный `.sql` |
| **служебный комментарий** | строка `-- ...` над оператором в `.sql`-скрипте (префиксы `BREAKING:` и `review:`) |

## Язык текстов

Надпись на полях вывода, которая экономит время при ревью:

- **Русский** — javadoc и комментарии в коде, консольная сводка, `--help`, тексты исключений и
  `log.warn`.
- **Английский** — всё, что попадает в артефакты: значения `description` в JSON-отчёте,
  служебные комментарии в `.sql` (включая маркеры `BREAKING:` и `review:`), сами SQL-операторы и
  имена enum'ов. Отчёты сравниваются между прогонами и подаются в `psql`, поэтому их текст
  стабилен и не локализуется.

## Чего в документации сознательно нет

- Ссылок на внешние трекеры и процессы релизного цикла — их у проекта нет.
- Описания возможностей, которых нет в коде (представления, секционирование, гранты,
  хранимые процедуры). Такие темы перечислены как **ограничения**, а не как «план».
- Примеры с реальными паролями или строками подключения рабочей среды.
